OpenShift

oc extends kubectl with OpenShift-specific project, build, and security workflows — every plain kubectl command still works, this is what's on top.

# authenticates the CLI against a cluster's API server, prompts for credentialsoc login https://api.cluster.example.com:6443 -u <username>
# confirm current user, useful after switching contexts/loginsoc whoami
# create + switch to a new project (OpenShift's namespaced wrapper)oc new-project <project_name>
# switch between existing projectsoc project <project_name>
# deploy straight from a container imageoc new-app --image=<registry>/<image>:<tag> --name=<app_name>
# expose a service with TLS-terminated Route (OpenShift's built-in Ingress)oc create route edge <route_name> --service=<service_name> --port=<port> --hostname=<hostname>
# list exposed routes and their hostnamesoc get routes
# shorthand for exec -it ... shoc rsh mypod
# every project you can see, across the clusteroc get projects
# delete a project and everything in it — destructiveoc delete project <project_name>
# quick visual summary of what's deployed in the current projectoc status
# follow logs for a DeploymentConfig (OpenShift's pre-Deployment resource, still common on older clusters)oc logs -f dc/myapp
# list builds if using OpenShift's built-in S2I/BuildConfig pipelineoc get build
# manually trigger a new buildoc start-build myapp
Enhanced 
# grant a Security Context Constraint to a service account — needed when a pod legitimately requires a UID the default restricted-v2 SCC blocksoc adm policy add-scc-to-user anyuid -z <service_account> -n <project>
# list available SCCs and what each permitsoc get scc
# safely empty a node before maintenance — cordon first so nothing new schedules there, then drainoc adm cordon <node_name> && oc adm drain <node_name> --ignore-daemonsets --delete-emptydir-data
# node-level resource usage, cluster-wideoc adm top nodes
# namespace-level pod resource usageoc adm top pods --sort-by=cpu -n <project>
# check current cluster version and available upgrade pathoc adm upgrade
# project-scoped event stream, chronological — same idea as kubectl get events -A, narrowed downoc get events --sort-by='.lastTimestamp' -n <project>

Health check
  1. Correct project active — oc project — red flag: you're in the wrong project — a classic way to "fix" the wrong environment.
  2. Route actually admitted — oc get routes — red flag: missing an ADMITTED status — the route exists but isn't actually being served.
  3. No SCC denials — oc get events -n <project> | grep -i scc — red flag: any "unable to validate against any security context constraint" — the pod isn't just failing, it's being actively blocked.

Troubleshooting

Pod denied by Security Context Constraint:

# the denial reason is in the event, naming the exact SCC rule that blocked itoc get events -n myproject --sort-by='.lastTimestamp' | grep -i scc
# see exactly what the default SCC does and doesn't allowoc get scc restricted-v2 -o yaml

Before granting a broader SCC like anyuid, check whether the image can just be rebuilt to not need root — it's the safer fix and the one that survives a security review.

Route returns 503 or doesn't resolve:

# confirm the route actually points at the right service and portoc get route myroute -o yaml
# empty endpoints means the service has no healthy pods behind it — the route is fine, the backend isn'toc get endpoints myservice
