Health check
  1. Node health — kubectl get nodes — red flag: any node NotReady.
  2. Pod status cluster-wide — kubectl get pods -A | grep -v Running — red flag: anything not Running or Completed.
  3. Recent events — kubectl get events -A --sort-by='.lastTimestamp' — red flag: the same Warning event repeating on one object — a single event is often noise, a repeat is a pattern.
  4. Resource pressure — kubectl top nodes — red flag: any node near 100% CPU or memory — new pods may be failing to schedule because of it.

Troubleshooting

Pod stuck in Pending:

# events at the bottom almost always say why — insufficient CPU/memory, no matching node, unbound PVCkubectl describe pod mypod# confirm there's actually capacity to schedule ontokubectl get nodes -o wide

Pod stuck in ImagePullBackOff:

# wrong image tag, private registry auth missing, or a typo in the image name — the event message names which onekubectl describe pod mypod | grep -A5 Events# confirm the pull secret actually exists in this namespace, secrets don't cross namespaceskubectl get secret <registry_secret> -n mynamespace

CrashLoopBackOff:

# the crash reason is in the PREVIOUS container's logs, not the new one that just startedkubectl logs mypod --previous# exit code and reason without digging through full logskubectl describe pod mypod | grep -A3 "Last State"
