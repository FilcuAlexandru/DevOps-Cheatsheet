Basic

 
# list every cluster/context you have configuredkubectl config get-contexts
# switch clusters — check this before anything destructivekubectl config use-context mycontext
# stop typing -n myns on every commandkubectl config set-context --current --namespace=myns
# multiple resource types in one callkubectl get pods,svc,deploy -n myns
# create or update from a manifestkubectl apply -f manifest.yaml
# remove everything defined in that manifestkubectl delete -f manifest.yaml
# scale up/down manuallykubectl scale deployment/myapp --replicas=3
# reach a cluster service from localhost, no ingress neededkubectl port-forward svc/myapp 8080:80
# copy a file out of a running podkubectl cp mypod:/var/log/app.log ./app.log
# newest pods last, useful after a rolloutkubectl get pods -o wide --sort-by=.status.startTime
# needs metrics-server, but invaluablekubectl top pods --sort-by=memory
# events at the bottom are usually the real answerkubectl describe pod mypod
# logs from the container BEFORE the last crash — the one you actually need for CrashLoopBackOffkubectl logs -f mypod --previous
# cluster-wide event stream, chronologicalkubectl get events --sort-by='.lastTimestamp' -A
kubectl exec -it mypod -- sh
# create a namespacekubectl create namespace myns
# delete a namespace and everything in it — destructivekubectl delete namespace myns
# every common resource type in a namespace at oncekubectl get all -n myns
# attach a label to a running resourcekubectl label pod mypod env=prod
# attach metadata that isn't used for selection, unlike labelskubectl annotate pod mypod note="value"
# full resource definition as YAML, including server-set fieldskubectl get pod mypod -o yaml
# open a live resource in $EDITOR, applies on savekubectl edit deployment myapp
# update just the image of a container, no manifest edit neededkubectl set image deployment/myapp app=myapp:v2
# watch a rollout until it completes or failskubectl rollout status deployment/myapp
# quickly create a Service for an existing Deploymentkubectl expose deployment myapp --port=80 --target-port=8080
Enhanced 
# ephemeral debug pod on a node, no SSH neededkubectl debug node/mynode -it --image=busybox
# attach a debug container to a running pod (great when the app image has no shell)kubectl debug mypod -it --image=busybox --target=mypod
# see exactly what would change, before you applykubectl diff -f manifest.yaml
# server-side validation without applyingkubectl apply -f manifest.yaml --dry-run=server
# built-in field docs, no browser neededkubectl explain deployment.spec.strategy
# instant rollback to the previous revisionkubectl rollout undo deployment/myapp
# see all revisions before deciding which to roll back tokubectl rollout history deployment/myapp
# OpenShift shorthand for exec -it ... shoc rsh mypod
# OpenShift admin-level resource viewoc adm top pods --sort-by=cpu -n mynamespace
# filter server-side instead of piping through grepkubectl get pods --field-selector=status.phase=Running -A
# filter by label selector, see every label on the resultkubectl get pods -l app=myapp --show-labels
# target a specific container inside a multi-container podkubectl exec -it mypod -c sidecar -- sh
# same idea for kubectl cp with multiple containerskubectl cp mypod:/etc/config.yaml ./config.yaml -c sidecar
# extract exactly one field, scriptable, no jq neededkubectl get pod mypod -o jsonpath='{.status.podIP}'

# check what a specific service account can dokubectl auth can-i delete pods --as=system:serviceaccount:myns:mysa

Health check
  1. Node health — kubectl get nodes — red flag: any node NotReady.
  2. Pod status cluster-wide — kubectl get pods -A | grep -v Running — red flag: anything not Running or Completed.
  3. Recent events — kubectl get events -A --sort-by='.lastTimestamp' — red flag: the same Warning event repeating on one object — a single event is often noise, a repeat is a pattern.
  4. Resource pressure — kubectl top nodes — red flag: any node near 100% CPU or memory — new pods may be failing to schedule because of it.

Troubleshooting

Pod stuck in Pending:

# events at the bottom almost always say why — insufficient CPU/memory, no matching node, unbound PVCkubectl describe pod mypod
# confirm there's actually capacity to schedule ontokubectl get nodes -o wide

Pod stuck in ImagePullBackOff:

# wrong image tag, private registry auth missing, or a typo in the image name — the event message names which onekubectl describe pod mypod | grep -A5 Events
# confirm the pull secret actually exists in this namespace, secrets don't cross namespaceskubectl get secret <registry_secret> -n mynamespace

CrashLoopBackOff:

# the crash reason is in the PREVIOUS container's logs, not the new one that just startedkubectl logs mypod --previous
# exit code and reason without digging through full logskubectl describe pod mypod | grep -A3 "Last State"
