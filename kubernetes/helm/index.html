Kubernetes / Helm

Helm

23 COMMANDS INDEXED

Helm is the package manager for Kubernetes — bundles of templated manifests (charts) with configurable values, installed as a named "release."

# add a chart repositoryhelm repo add bitnami https://charts.bitnami.com/bitnami
# refresh the local index of available chartshelm repo update
# find a chart across added reposhelm search repo <name>
# install, overriding one value inlinehelm install <release_name> <chart> --set <key>=<value>
# upgrade using a full values file instead of one-off --set flagshelm upgrade <release_name> <chart> -f custom-values.yaml
# every release across every namespacehelm list -A
# revision history for a releasehelm history <release_name>
# roll back to a specific prior revisionhelm rollback <release_name> <revision_number>
# remove a release entirelyhelm uninstall <release_name>
# every configurable value a chart exposes, with its defaulthelm show values <chart>
# chart metadata — version, description, dependencieshelm show chart <chart>
# the exact rendered YAML currently applied for a releasehelm get manifest <release_name>
# fetch/update a chart's subchart dependencieshelm dependency update <chart>
Enhanced 
# atomic upgrade: automatically rolls back if anything fails health checks — much safer than a bare upgrade for anything production-facinghelm upgrade --install <release_name> <chart> --atomic --timeout 5m
# render the final YAML locally, no cluster contact — see exactly what would be applied before it touches anythinghelm template <release_name> <chart> -f values.yaml
# catch chart syntax/best-practice issues before packaging or installinghelm lint <chart>
# see the actual values currently in effect for a running release, not just what's in your local filehelm get values <release_name>
# (needs the helm-diff plugin) preview exactly what an upgrade would change — the Helm equivalent of kubectl diffhelm diff upgrade <release_name> <chart> -f values.yaml

Health check
  1. Release status — helm status <release_name> — red flag: anything other than deployed.
  2. Recent history — helm history <release_name> — red flag: the most recent revision shows failed or superseded right after a fresh install (a bad rollout that never got cleaned up).
  3. No drift from what's declared — helm diff upgrade <release_name> <chart> -f values.yaml (needs the plugin) — red flag: unexpected differences — someone patched the cluster directly instead of through Helm.

Troubleshooting

Release stuck in pending-upgrade or pending-install:

# confirm it's actually stuck, not just slowhelm status myrelease
# find the last known-good revisionhelm history myrelease
# Helm's lock on a stuck release lives in a Secret — removing it (carefully) unblocks the next helm commandkubectl delete secret -l owner=helm,name=myrelease,status=pending-upgrade -n mynamespace

Upgrade fails halfway through:

# if --atomic wasn't used, roll back manually to the last good revisionhelm rollback myrelease
# use --atomic next time so a failed upgrade rolls back automatically instead of leaving things half-appliedhelm upgrade myrelease mychart --atomic --timeout 5m
