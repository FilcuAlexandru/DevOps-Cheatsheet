Kubernetes / ArgoCD

ArgoCD

20 COMMANDS INDEXED

ArgoCD syncs cluster state to match what's declared in Git — the core of a GitOps workflow. Most day-to-day work is checking whether an app is actually in sync, and why it isn't.

# authenticate the CLI against an ArgoCD serverargocd login <argocd_host> --username <username>
# every application ArgoCD is managing, with sync/health status at a glanceargocd app list
# detailed status for one app — sync state, health, resourcesargocd app get <app_name>
# trigger a manual sync (pull latest from Git, apply to cluster)argocd app sync <app_name>
# see exactly what's different between Git and the live cluster state, before syncingargocd app diff <app_name>
# every past sync, with revision and timestampargocd app history <app_name>
# roll back to a specific prior syncargocd app rollback <app_name> <history_id>
# remove an app from ArgoCD (has its own flag for whether to also delete the underlying resources)argocd app delete <app_name>
# ArgoCD projects — groupings that scope which repos/clusters/namespaces an app can useargocd proj list
# stream logs for an app's pods directly through the ArgoCD CLI, no kubectl context switch neededargocd app logs <app_name> -f
Enhanced 
# sync and also remove resources that were deleted from Git (off by default — a normal sync leaves orphaned resources alone)argocd app sync <app_name> --prune
# turn on full GitOps automation: auto-sync on Git changes, prune removed resources, and revert manual cluster drift automaticallyargocd app set <app_name> --sync-policy automated --auto-prune --self-heal
# block until an app reports healthy — useful in CI/CD pipelines after triggering a syncargocd app wait <app_name> --health
# list every Kubernetes resource this app owns, with individual healthargocd app resources <app_name>
# Git repositories ArgoCD is configured to pull fromargocd repo list
# every cluster ArgoCD can deploy to, if managing more than oneargocd cluster list

A common source of confusion: auto-sync ≠ self-heal. Auto-sync reacts to Git changes; self-heal reacts to someone changing the live cluster directly (kubectl edit, a manual patch) and reverts it back to match Git. Enable both if the goal is "the cluster can never drift from Git," enable only auto-sync if manual emergency patches should be tolerated until the next intentional sync.

Health check
  1. Sync status — argocd app get <app_name> — red flag: OutOfSync — Git and the live cluster have diverged.
  2. Health status — same command, different field — red flag: Degraded or Missing — the resources exist but aren't actually healthy.
  3. Last sync result — argocd app history <app_name> — red flag: the most recent sync shows Failed, not just an older one — a stale failure isn't urgent, a fresh one is.

Troubleshooting

App shows OutOfSync but sync doesn't fix it:

# see exactly what's different — sometimes it's a field a controller keeps overwriting (e.g. replica count under an HPA)argocd app diff myapp
# for known &quot;always drifting&quot; fields, tell ArgoCD to leave them alone rather than fighting a controllerargocd app set myapp --sync-option ApplyOutOfSyncOnly=true

App is Healthy in ArgoCD but the app itself seems broken:

# health here means &quot;Kubernetes resources reached their expected state&quot; — it does NOT mean your application logic is workingargocd app resources myapp
# ArgoCD's health check passed the baton — actual app health is on you from herekubectl logs -f deployment/myapp -n mynamespace
