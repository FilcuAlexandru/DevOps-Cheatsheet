Service management and systemd's own journal — a structured, indexed log store, separate from plain-text application log files.

# follow, like tail -f but for the journaljournalctl -u myservice -fjournalctl -u myservice --since "1 hour ago"# errors only, this bootjournalctl -p err -b# kernel messages only (dmesg equivalent)journalctl -k# how much space the journal itself is usingjournalctl --disk-usage# structured output, pipeable to jqjournalctl -o json-pretty -u myservice
Enhanced

journalctl -f -u myservice --output=cat strips the timestamp/hostname prefix — much easier to read when you just want the app's own log lines.

systemctl status myservice# everything currently broken, system-wide, one commandsystemctl list-units --failed# pull specific properties, scriptablesystemctl show myservice -p MainPID -p ActiveState# what's slowing down boot, sortedsystemd-analyze blame# the actual dependency chain that determines boot timesystemd-analyze critical-chain# drop-in override without touching the vendor unit filesystemctl edit myservice# required after any unit file changesystemctl daemon-reload# stronger than disable — prevents even manual startsystemctl mask myservice

Health check
  1. Is it active — systemctl is-active myservice — red flag: anything other than active.
  2. Recent restarts — systemctl show myservice -p NRestarts — red flag: a climbing count means a crash loop, not a one-off.
  3. Other failed units — systemctl list-units --failed — red flag: unrelated services also failed at the same time — points to a shared cause (disk, network) rather than this one service.
  4. Journal around the failure — journalctl -u myservice -p err --since "10 min ago" — red flag: errors clustered right before it went down.

Troubleshooting

Service fails to start with no obvious error:

# -l shows the full text, not truncated — the real error is often cut off without itsystemctl status myservice -l# -x adds explanatory help text for common failure codes, -e jumps to the endjournalctl -xeu myservice

Changed the unit file but nothing happened:

# required after ANY change to a unit file — systemd caches the old definition otherwisesystemctl daemon-reload# confirm which file it's actually reading from — a stray override elsewhere is a common surprisesystemctl show myservice -p FragmentPath

Journal is using too much disk:

# confirm it's actually the journal, not something elsejournalctl --disk-usage# shrink the journal down to a target size, oldest entries dropped firstjournalctl --vacuum-size=500M# or keep by age instead of size — whichever matches your retention needjournalctl --vacuum-time=7d
