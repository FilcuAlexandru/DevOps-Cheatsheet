Health check
  1. Container state — docker ps -a — red flag: Restarting (loop) or Exited with a non-zero code.
  2. Resource usage — docker stats --no-stream — red flag: memory usage sitting right at its limit — OOM-kill is imminent, not hypothetical.
  3. Recent events — docker events --since 10m — red flag: repeated die or oom events for the same container.
  4. Disk — docker system df — red flag: total usage approaching the host's actual free disk, not just a high "reclaimable" number (that part is normal and expected).

Troubleshooting

Container exits immediately after starting:

# almost always shows the actual error, even for a container that's already stoppeddocker logs mycontainer
# exit code — 137 usually means OOM-killed, 1 is a generic app errordocker inspect mycontainer --format '{{.State.ExitCode}}'
# override the entrypoint to get a shell instead, poke around manuallydocker run -it --entrypoint sh myimage

"No space left on device" but df shows free space:

# Docker's own disk usage, separate from the host filesystem viewdocker system df
# Docker images/layers/volumes accumulate in their own storage driver — this is almost always the real causedocker system prune -af --volumes

Two containers can't reach each other:

# confirm both containers are actually on the same networkdocker network ls
# see which containers are attached, and their IPsdocker network inspect <network_name>
# containers on the same user-defined network can reach each other by name — if this fails, they're not on the same networkdocker exec mycontainer1 ping mycontainer2
