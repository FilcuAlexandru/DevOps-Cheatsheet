Health check
  1. Instance status — SELECT open_mode FROM v$database; — red flag: anything other than READ WRITE when you expect the DB to be fully open.
  2. Session count — SELECT count(*) FROM v$session; — red flag: approaching sessions parameter limit — new connections will start failing soon.
  3. Tablespace usage — dba_tablespace_usage_metrics — red flag: any tablespace above 90% used.
  4. Alert log — tail the current alert log — red flag: any ORA- error, especially repeating ones — a single old one in history is not urgent, a fresh repeating one is.

Troubleshooting

Database won't accept connections:

# is the listener even uplsnrctl status
# is the instance actually open, or stuck in MOUNTsqlplus / as sysdba <<< "SELECT status FROM v\$instance;"

Archiver stuck / "ORA-00257: archiver error":

-- almost always the recovery area filling upSELECT * FROM v$flash_recovery_area_usage;
# clear old archived logs older than 3 days — adjust the window to your actual recovery needs before runningrman target / <<< "DELETE ARCHIVELOG ALL COMPLETED BEFORE 'SYSDATE-3';"

Tablespace full:

-- confirm which one, firstSELECT tablespace_name, ROUND(used_percent, 1)
  FROM   dba_tablespace_usage_metrics
  WHERE  used_percent > 90;
-- add space; autoextend prevents an immediate repeatALTER TABLESPACE mytablespace ADD DATAFILE '/path/to/new_datafile.dbf' SIZE 500M AUTOEXTEND ON;
